# Disbit — визуальное техническое задание

Версия 1.0 · 18 октября 2026 · направление «Путь» · основной рынок: РФ.

Документ для владельца продукта, дизайнера и разработчика. Он определяет, как перенести функциональность существующего приложения в согласованный новый дизайн. Интерактивный образец: `design-mockups/path-prototype.html`. Функциональная основа: текущее приложение в `frontend/` и его API в `backend/`.

## 1. Что именно делаем

Disbit — личная история про обещания и движение к цели. Повседневная часть должна быть спокойной и понятной; ощущение приключения создаёт персонаж и маршрут марафона.

Визуальный результат: тёмно-синий интерфейс, ясные карточки, умеренные цветовые акценты, детализированный человек-путешественник и светлое стеклянное нижнее меню Light Glass. Стекло используется для навигации; основные карточки остаются плотными и хорошо читаемыми.

### 1.1. Граница этого задания

1. Сохранить все функции существующей версии и уже сделанные исправления беты.
2. Изменить композицию, типографику, иконки, иллюстрации, материалы и анимации.
3. Сохранить данные пользователя, настройки, купленные предметы, историю и связи между сущностями.
4. Описать все важные состояния, включая отсутствие данных и ошибки.
5. Переносить дизайн в основное приложение поэтапно, проверяя каждый сценарий.

Текущий макет показывает выбранный стиль и часть взаимодействий. Наличие элемента в макете не означает готовность соответствующего API или нативной функции. Новая версия не считается завершённой только потому, что повторяет пять демонстрационных экранов.

### 1.2. Что сохраняется на уровне поведения

Сохраняем правила расписаний, счётчиков, минимума, серий, грэйс-дней, марафонов, битов, наград, дружбы и денежных записей. При визуальном переносе не менять суммы, цены, лимиты, получателей, способы расчёта или доступность операций.

Отмена выполнения остаётся доступной через осознанное действие с подтверждением, как в исправленной прошлой версии. В демонстрационном макете повторная отметка заблокирована; этот упрощённый вариант не заменяет полный сценарий отмены.

## 3. Цветовая система

### 3.1. Основные токены

| Токен | Значение | Применение |
|---|---|---|
| Фон | `#0B1324` | Основной экран, шапка, фон диалогов |
| Карточка | `#14233B` | Обещания, секции, финансовые операции |
| Основное действие | `#4E78FF` | Главная кнопка, выбор, акцент навигации |
| Успех | `#36C58A` | Выполнено, положительный прогресс |
| Предупреждение | `#F3B44B` | Пропуск, внимание, приближающийся срок |
| Ошибка | `#EE6A5F` | Ошибка, отрицательная сумма, удаление |
| Основной текст | `#F4F7FF` | Заголовки и важные значения |
| Вторичный текст | `#AEBBD1` | Даты, подписи, дополнительная информация |
| Граница | `#2B3C56` | Разделение плотных поверхностей |
| Поднятая поверхность | `#1B2E49` | Выбранные сегменты, второстепенный слой |

Название Disbit на тёмном фоне — светлое, точка синяя. Историческое требование о тёмной надписи относилось к светлой версии. В светлом стеклянном меню используется отдельный тёмный текст, описанный ниже.

### 3.2. Правила применения

1. Основной фон и фон обычных карточек совпадают с заданными HEX-кодами.
2. Цвет обещания применяется к боковому акценту и иконке. Фон карточки сохраняется `#14233B`; текст остаётся читаемым.
3. Цвет не является единственным признаком: выполнение имеет галочку и текст, пропуск — отдельный символ и подпись, ошибка — сообщение.
4. Пустыня использует приглушённые природные оттенки внутри иллюстрации. Они не перекрашивают интерфейс.
5. Существующие восемь тем и купленные темы сохраняются. Эта палитра — новая стандартная тема. Остальные получают такие же компоненты и проверку контраста, без потери владения.
6. На синей заполненной кнопке текст `#0B1324`: контраст около 4,8:1. На зелёной и коралловой заполненных кнопках также используется тёмная надпись.
7. Вторичный текст на карточке имеет контраст около 8,1:1. Для обычного текста держать минимум 4,5:1, для значимых графических контролов — 3:1.

## 4. Размеры, сетка и типографика

### 4.1. Базовая сетка

Проектируем базовый экран 390 × 844 логических единицы. В вебе это CSS px; нативная реализация использует логические единицы платформы. Обязательные проверки: 320, 360, 390 и 430 по ширине; короткий экран 320 × 568.

1. Горизонтальные поля контента — 16; на узком экране не меньше 12.
2. Интервал между карточками — 8; между разделами — 24; между заголовком секции и списком — 12.
3. Внутренние поля карточки — 12–16; в крупном диалоге — 20–24.
4. Высота шапки — 64–70 плюс системная безопасная область.
5. Заголовок и главный счётчик выравниваются по одной визуальной линии.
6. Нижний запас прокрутки учитывает высоту плавающего меню, отступ и safe area. Последний контрол всегда можно прокрутить выше меню.
7. На планшете/десктопе ограничить ширину прикладной области; не растягивать телефонную карточку на весь монитор.

Текст остаётся понятным при увеличении размера до 200%: карточки растут по высоте, значения не наезжают на действия.

## 5. Нижнее меню — Light Glass

### 5.1. Внешний вид

Это плавающая светлая стеклянная капсула на тёмном фоне. На вебе материал воспроизводится прозрачностью, размытием и светлой кромкой.

| Параметр | Значение |
|---|---|
| Боковой отступ | 12 с учётом safe area |
| Отступ снизу | `max(12px, env(safe-area-inset-bottom))` |
| Высота | 72 |
| Радиус | 28 |
| Внутренние поля | 6 |
| Материал | `rgba(232, 239, 250, 0.86)` |
| Размытие | `blur(24px)` |
| Насыщенность | `saturate(140%)` |
| Кромка | 1 px, белый с непрозрачностью 70% |
| Верхний блик | Внутренний 1 px, белый 80% |
| Тень | Мягкая, смещение 12, размытие 32, тёмно-синяя |
| Текст и обычные иконки | `#25364F` |
| Текст активного раздела | `#19335B` |
| Активная иконка | `#315AE0` |
| Подложка активного раздела | Синий `#4E78FF` с непрозрачностью 14% |
| Центральная кнопка | 40 × 40, радиус 14, фон `#4E78FF` |

Пять позиций: «Сегодня», «Марафон», «Создать» с плюсом, «Друзья», «Профиль». Текущий пример сохраняет эти названия. Прежний раздел «Аватар» полностью доступен внутри «Марафон» через «Персонаж и биты», а фото профиля — через редактирование профиля.

### 5.2. Поведение

1. Области равной ширины, каждая зона нажатия минимум 44 × 44.
2. Иконка 23–24; подпись всегда видна. Только цветом активность не обозначать: есть подложка и `aria-current`.
3. Плюс открывает выбор создания: обещание, марафон/цель, идея на будущее. Он не стирает уже заполненную форму при случайном переключении.
4. Контент прокручивается под стеклом. Запас снизу позволяет увидеть и нажать последнюю строку полностью.
5. Нажатие даёт короткую обратную связь без изменения геометрии меню.
6. При открытой полноэкранной камере или сцене выполнения меню скрыто.
7. При открытой мобильной клавиатуре меню уступает место форме; поле и кнопка сохранения остаются доступными.
8. Сохраняются системная кнопка «назад», история переходов и возвращение к позиции списка.
9. Магнификация, перетаскиваемая линза и выход иконок за капсулу не применяются.
10. При reduced transparency, повышенном контрасте или отсутствии поддержки blur использовать плотный `#E8EFFA`. При повышенном контрасте активность дополнительно обозначается обводкой.

### 5.3. Приёмка меню

- На ширине 320 весь док и все пять подписей находятся внутри экрана.
- При safe area 34 нижняя кромка располагается выше системной области.
- На светлом и тёмном содержимом под стеклом подписи остаются читаемыми.
- Клавиатурный фокус хорошо виден и не обрезается краями капсулы.
- Меню не перекрывает последний контрол после прокрутки.
- Reduced transparency показывает плотную светлую капсулу без размытия.

## 6. Навигация и состав экранов

Основные разделы: «Сегодня», «Марафон», «Создать», «Друзья», «Профиль».

Вложенные экраны:

- «Сегодня»: детали обещания, статистика обещания, выбранный день, итог дня, пруф и шаринг.
- «Марафон»: список марафонов и целей, детали, создание/редактирование, итог, персонаж, снаряжение, сцены, биты и открытия.
- «Друзья»: добавление, приглашение, QR, доска сравнения, совместное обещание.
- «Профиль»: редактирование, достижения, награды, мотивация, календарь, общая статистика, депозит, аккаунт, настройки, данные, документы.

Вложенный экран имеет заголовок и понятную кнопку назад 44 × 44. Закрытие шторки возвращает к исходной карточке. Вводимые данные сохраняются как черновик до явного отказа либо успешного сохранения.

## 7. Экран «Сегодня»

### 7.1. Порядок блоков

1. Логотип и дата слева; профиль и/или итог дня справа без перегрузки шапки.
2. Короткий заголовок и счётчик выполненного за выбранный день.
3. Компактная полоса недели с выбранной датой и доступом в календарь.
4. Карточка активного марафона. Если их несколько — выбранная карточка и действие «Все марафоны».
5. Закреплённые обещания, если они есть.
6. Основной список обещаний.
7. «Не сегодня», если включено в настройках.
8. Итог дня и доступная личная награда — компактными блоками по состоянию.

Если марафона нет, показывается компактное приглашение создать его, а не пустая высокая иллюстрация. При первом запуске главный CTA — «Дать обещание».

### 7.2. Карточка обещания

Слева: цветовой акцент и иконка. В центре: название и одна наиболее полезная подпись. Справа: выполнение или счётчик. Штраф и совместность показываются отдельными компактными признаками, если они относятся к обещанию.

Подпись выбирается по контексту: «3 из 5 на неделе», «Серия 12 дней», «Минимум выполнен», «Пропуск · серия сохранена». Нельзя одновременно помещать пять равнозначных строк мелким шрифтом.

Состояния карточки:

| Состояние | Оформление и действия |
|---|---|
| Не выполнено | Нейтральная карточка, контурная кнопка выполнения |
| Частичный счётчик | Текущее/целевое число, плюс/минус с прежними ограничениями |
| Выполнено | Зелёная галочка; отмена через детали с подтверждением |
| Выполнен минимум | Отдельная подпись и значок; не выдавать за полное действие |
| Использован грэйс-день | Янтарная пауза и «Серия сохранена» |
| Не запланировано | Нейтральный статус «Не сегодня» |
| Сохранение | Индикатор в области действия; повторный запрос заблокирован |
| Ошибка сохранения | Текст причины и повтор; без ложной окончательной отметки |
| Недоступная старая блокировка | Видимая подпись; сохранённые условия доступны в деталях |

### 7.3. Сценарии

1. Нажатие на текст карточки открывает детали; на отдельный круг — выполняет обещание.
2. После подтверждения записи обновляются серия, биты и связанные марафоны.
3. Шаринг и необязательное фото следуют после отметки; закрытие камеры не отменяет выполнение.
4. Повторный тап по выполнению не снимает галочку автоматически.
5. Действие «Использовать грэйс-день» находится отдельно, показывает остаток и последствия.
6. Список не прыгает при смене статуса; положение прокрутки сохраняется.

## 8. Создание и редактирование обещания

### 8.1. Состав формы

1. Название, счётчик допустимой длины только при приближении к лимиту.
2. Иконка и акцент карточки с живым предпросмотром.
3. Расписание: переключатель «По дням» / «N дней в неделю».
4. Для конкретных дней — семь кнопок; для гибкого режима — компактный выбор числа 1–7. Под ним не нужен постоянный абзац объяснения.
5. Тип цели: «Отметка» / «Счётчик». Для счётчика — цель и единица измерения.
6. «Минимум» как необязательное поле внутри дополнительных условий.
7. Последствие: текущий денежный режим с суммой и получателем; недоступная блокировка остаётся явно обозначенной.
8. Перед сохранением — читаемая сводка: что, когда и какие последствия пользователь выбрал.
9. Кнопки «Создать обещание» или «Сохранить изменения» и отмена.

### 8.2. Требования

- Сохраняются текущие ограничения длины имени, минимального действия, единиц, сумм и допустимых дней.
- Дополнительные секции раскрываются без потери введённых значений.
- Изменение цвета сразу видно в предпросмотре, после сохранения и после синхронизации.
- Ошибка показывается у поля; фокус переводится на первое ошибочное поле.
- При ошибке сети форма остаётся заполненной.
- Правка не меняет историю прошлых условий и финансовых записей как побочный эффект оформления.
- В существующем обещании недоступная блокировка не заменяется денежным режимом без явного выбора пользователя.

## 9. Детали, отмена и удаление обещания

1. Верх: название, иконка и статус дня.
2. Основные показатели: серия, недельное выполнение, цель, минимум.
3. Условия: расписание, сумма и получатель, связанный марафон и друг.
4. Действия: редактировать, статистика, поделиться, делать вместе, закрепить/открепить.
5. Дополнительные действия: минимум, грэйс-день и подтверждённая отмена — только где они доступны.
6. Удаление находится внизу и визуально отделено.

Диалог отмены объясняет, что произойдёт с отметкой, битами и шагом марафона. Диалог удаления содержит имя обещания и фактические последствия для истории и связей. История денежных операций не исчезает из-за нового оформления.

Безопасная кнопка получает первоначальный фокус. Двойной тап не запускает повторную операцию. При отказе сервера сущность и её данные остаются доступны.

## 10. Пруф, камера и «Поделиться»

### 10.1. Визуальный сценарий

1. После выполнения предложить «Поделиться моментом» и спокойное «Без фото».
2. Перед запросом камеры кратко объяснить действие; системное разрешение запрашивать по нажатию.
3. В камере: крупная область кадра, фото/видео, переключение камеры при наличии, затвор и закрытие.
4. Для видео: заметные запись, таймер и остановка. Сохраняются действующие лимиты формата и размера.
5. Предпросмотр: «Переснять», «Отправить», «Без фото».
6. Загрузка: индикатор, запрет повторного отправления, понятная возможность повторить после ошибки.
7. Системный шаринг использует результат и реальный адрес Disbit; отмена шаринга возвращает в приложение.

### 10.2. Критические различия

«Без фото», «Не делиться» и «Пропустить день» — три разных действия. Первые два сохраняют выполнение. Последнее расходует грэйс-день по правилам и не начисляет бит или шаг.

Обязательны экраны отказа в доступе, отсутствия камеры, ошибки файла, превышения размера, прерванной загрузки и отсутствия сети. Нельзя показывать успешную отправку до подтверждения сервера.

Шаблон карточки для шаринга: изображение персонажа, название выполненного обещания, короткий результат, дата и небольшой логотип. Суммы, личный текст мотивации и закрытые данные друзей не добавлять автоматически.

## 11. Марафоны и большие цели

### 11.1. Главный экран раздела

1. Заголовок «Марафон» и вход «Персонаж и биты».
2. Активный маршрут с крупной сценой, шагом и сроком.
3. Связанные обещания и их сегодняшнее состояние.
4. Другие марафоны и ручные цели — доступным списком.
5. Создание новой цели и завершённые результаты.

### 11.2. Создание

1. Название и иконка.
2. Срок — необязательный, как в прошлой версии.
3. Количество шагов и подсказка расчёта. Существующая ручная цель остаётся ручной.
4. Сцена маршрута с предпросмотром и статусом владения.
5. Выбор от 1 до 5 существующих обещаний для пошагового марафона.
6. Занятые другим марафоном обещания видны, но недоступны, с названием текущей связи.
7. Итоговая сводка и подтверждение.

Сохраняются правило «одно обещание — один марафон», дата старта и учёт только соответствующих выполнений. Создание марафона не создаёт одноимённое обещание и денежные условия автоматически. При нескольких марафонах сохранение нового не заменяет предыдущий — демонстрационное упрощение макета в рабочую версию не переносить.

### 11.3. Сцены и цели

Сохраняются шесть существующих сцен: пустыня, океан, Луна, Эверест, джунгли, Антарктида. Пустыня — бесплатная сцена по умолчанию с детализированным человеком. Для остальных сохраняются соответствующие движения: плавание, шаг, восхождение, движение через снег.

Ручные цели отображаются без фиктивного шага персонажа. Существующие кнопки изменения прогресса и достижения 100% сохраняются. Переименование и редактирование не начинают историю заново.

## 12. Персонаж и простые аватары

### 12.1. Персонаж по умолчанию

Взрослый человек-путешественник с естественными пропорциями, спокойным выражением лица и читаемым силуэтом. Стиль — детальная рисованная игровая иллюстрация, совместимая с интерфейсом. Не фотореализм.

Обязательные детали:

- лицо с глазами, носом, линией рта и тенями;
- походная шляпа с полями, лентой и объёмом тульи;
- рубашка/куртка с воротником, швами, манжетами и карманами;
- брюки с отдельными складками и карманом;
- рюкзак с лямками, поясом, пряжками, боковой бутылкой и спальником;
- ботинки со шнуровкой, отдельной подошвой и контактом с землёй;
- тень под ногами, согласованная с освещением сцены.

В маленькой карточке важен силуэт и снаряжение; на полном экране видны детали. Предметы не перекрывают лицо, прогресс и кнопку выхода.

### 12.2. Подготовка графики по подшагам

1. Зафиксировать пропорции, базовые цвета одежды и общий масштаб.
2. Разделить голову, торс, передние/задние руки и ноги, рюкзак и аксессуары.
3. Поставить корректные точки вращения суставов и крепления рюкзака.
4. Подготовить состояния: покой, шаг, успех, финиш, статичный reduced-motion.
5. Проверить персонажа на маленькой карточке, крупной сцене и фоне всех доступных маршрутов.
6. Подготовить совместимые варианты снаряжения. Если предмет не применим к сцене, показать причину до выбора.
7. Проверить отсутствие обрезанных конечностей, плавающих ног и мерцания контуров.

### 12.3. Аватар профиля

Фото/эмодзи/монограмма/открытый знак остаются отдельным выбором профиля. По умолчанию можно показывать простое изображение головы путешественника. Изменение фото профиля не заменяет персонажа марафона.

Нужны: выбор фото, текущая обработка изображения, предпросмотр, удалить фото, выбор эмодзи/знака и сохранение. Если пользователь уже выбрал аватар, редизайн его не сбрасывает.

Динозавры и другие альтернативные персонажи остаются ранее запрошенным расширением. Для них требуется отдельный комплект состояний и совместимости; наличие динозавра в старых эскизах не означает готовый каталог персонажей в рабочем приложении.

## 13. Биты, снаряжение и открытия

1. Вход из марафона и профиля ведёт на один раздел, без дублирующихся балансов.
2. Сверху виден баланс битов; рубли рядом не используются как та же валюта.
3. Категории: снаряжение, сцены, иконки, темы, знаки профиля, грэйс-дни.
4. Предмет имеет изображение, название, цену, статус «Открыто»/«Выбрано»/«Недоступно».
5. Нажатие на закрытый предмет открывает предпросмотр и подтверждение цены.
6. При нехватке битов показать нужную и текущую сумму и понятный путь к заработку.
7. Открытие не запускается повторно; уже купленное не покупается заново.
8. Выбранное снаряжение сразу обновляет превью и сцены, где оно применимо.

На дату ТЗ текущие цены: тема 40, сцена 120, снаряжение 60, иконка 25, грэйс-день 30, знак 80 бит. Эти числа фиксируют проверенную основу, а не предложение изменить экономику. Источник при реализации — конфигурация продукта.

Грэйс-дни: текущая основа — 5 в месяц, дополнительно можно открыть до 3 за биты. Использование сохраняет серию, не увеличивая её, и не выдаёт бит/шаг за пропущенный день. Уже зафиксированное списание не отменяется.

## 14. Полноэкранный шаг и финиш

1. После подтверждённого выполнения показать сцену, связанную именно с затронутым марафоном.
2. Отобразить персонажа крупно: ориентир 60–80% высоты области иллюстрации, а не экрана целиком.
3. Показать «Было 9/28 → Стало 10/28» без прыжка счётчика заранее.
4. Персонаж перемещается на видимый участок пути; движения рук, ног и рюкзака согласованы.
5. Короткая прогулка — около 700 мс. Кнопки выхода и продолжения работают сразу.
6. В режиме уменьшенного движения — статичная сцена, обновлённые цифры и мягкая смена состояния.
7. Финиш отличается текстом, позой и итогом маршрута; результат доступен повторно из завершённого марафона.
8. Повторный просмотр анимации не начисляет шаги и биты.

## 15. Друзья и совместные обещания

### 15.1. Композиция

1. Заголовок и заметное действие «Добавить друга».
2. Карточки друзей: аватар 48, имя, @логин, серия и выполнение недели.
3. Число совместных обещаний и вход к ним.
4. Доска сравнения с собственным результатом.
5. Приглашение: ссылка, копирование, системный шаринг и QR там, где он уже используется.

### 15.2. Взаимодействия

- Добавление по логину сохраняет текущую модель взаимной дружбы; редизайн не вводит неподдерживаемую систему заявок.
- Длинное имя не вытесняет меню действий; логин может переноситься.
- Отсутствующий показатель обозначается «Нет данных», а не придуманным числом.
- Удаление требует подтверждения; ошибка сервера сохраняет карточку.
- Приглашение в совместное обещание показывает реальные условия до принятия.
- Состояния: без аккаунта, пустой список, загрузка, ошибка и повтор, частично устаревшие данные, успешное добавление.

В интерфейсе не появляются чат, публичная лента или денежные соревнования как часть визуального переноса.

## 16. Календарь и прошлые дни

1. Заголовок месяца, стрелки по 44 × 44 и быстрый возврат к текущему месяцу.
2. Сетка 7 колонок; выбранный день и сегодняшний день различаются.
3. Статусы: выполнено, минимум, грэйс-день, невыполнено, не запланировано. Нужна доступная текстовая легенда.
4. Нажатие открывает день с полным списком обещаний и итогами.
5. Допустимые прошлые изменения сохраняются; закрытые дни показывают причину недоступности.
6. Отмена выполнения и в календаре проходит через подтверждение.
7. Уже зафиксированные финансовые операции не исчезают после редактирования отметки.
8. «На будущее»: список идей, добавить/удалить, «Начать» открывает заполненную форму обещания. Идея удаляется из списка после успешного создания.

## 17. Статистика и история

### 17.1. Общая статистика

Порядок: результат недели и сравнение с предыдущей → недельные столбцы → текущая/лучшая серия, всего выполнено и штрафы → heatmap за существующие 16 недель с фильтрами → список серий → история штрафов.

1. Диаграммы имеют подписи и доступное текстовое представление.
2. Не использовать красный для пустых/не запланированных дней.
3. Положительная динамика зелёная, отрицательная коралловая, отсутствие сравнимой базы — нейтральное.
4. Фильтры и выбранный период сохраняются при возврате.
5. Длинные суммы и большие серии не обрезаются бессмысленным многоточием.

### 17.2. Статистика обещания

Сохраняются текущие индивидуальные показатели, история и календарные отметки именно этого обещания. Заголовок всегда уточняет объект. При удалении/переименовании обещания финансовая история остаётся объяснимой.

## 18. Профиль, мотивация, награды, достижения

### 18.1. Профиль

Верх: аватар, имя, логин и редактирование. Далее компактные входы по группам: прогресс; деньги; аккаунт; настройки; данные и документы. Длинные формы настроек не раскрываются все сразу на стартовом профиле.

### 18.2. Мотивация

Сохраняются шкала 0–100 с текущим шагом и текст до существующего лимита. В режиме просмотра — небольшой текстовый блок и «Изменить»; при редактировании — поле, значение шкалы и сохранение. Чужим пользователям личный текст не показывается автоматически.

### 18.3. Личные награды

1. Список наград с порогом серии и статусом.
2. Создание: длина серии и текст награды.
3. Награда ещё закрыта / доступна / получена.
4. Доступная награда может появиться компактным баннером на «Сегодня».
5. Получение и удаление сохраняют текущие правила; анимация не подменяет сохранение.

### 18.4. Достижения

Сверху число открытых и общий прогресс. Далее «Получены» и «Ещё не открыты». Закрытые медали имеют название, условие и текущий прогресс. Полученные — полноценную иллюстрацию. Металлическая фактура уместна в самих медалях; интерфейс вокруг остаётся простым.

## 19. Депозит, пополнение, штрафы

### 19.1. Композиция

1. Баланс в рублях крупно, статус режима платежей рядом понятным текстом.
2. Основное действие «Пополнить».
3. История операций: тип, название обещания при наличии, дата, сумма и статус.
4. Детали операции — по нажатию, с доступной причиной/результатом.
5. Денежный баланс и биты оформлены разными обозначениями.

### 19.2. Состояния

- Без аккаунта — предложение войти вместо пустого кошелька.
- Загрузка — скелетон, не фиктивный нулевой баланс.
- Тестовый режим — явная подпись; изображение не создаёт впечатление реального перевода.
- Выбор суммы — пресеты и произвольное значение с сохранением текущих ограничений.
- Переход к оплате, возвращение, ожидание подтверждения, успех, отмена и ошибка.
- Недостаточно денег — ясное сообщение и доступное пополнение.
- Ошибка истории — повтор загрузки без стирания последнего известного результата.

Цвет отрицательной суммы — коралловый; положительной — зелёный. Перед отрицательной операцией отображается реальный минус, а не только цвет. Формат рубля и даты — российский.

Возврат неиспользованного депозита на исходный способ оплаты — ранее запрошенная отдельная функция, которой сейчас не хватает в рабочем контуре. Для неё резервируются экран суммы/способа и статусы, но кнопка становится рабочей только вместе с реализацией операции. Редизайн не имитирует возврат и не изменяет правила списаний.

## 20. Аккаунт, вход и первый запуск

1. Сохраняются вход по логину/почте и паролю, регистрация, показ пароля, проверка почты и повтор кода.
2. Сохраняется доступность локального режима там, где он предусмотрен текущей версией; облачная синхронизация не обещается без аккаунта.
3. Поля имеют постоянные понятные подписи, корректное автозаполнение и действия клавиатуры.
4. Ошибка относится к конкретному полю или запросу и сохраняет заполненные данные.
5. Смена аккаунта не показывает данные предыдущего пользователя.
6. Онбординг сохраняет существующие вопросы, выбранные ответы, возврат к предыдущему шагу и переход к приложению. Оформление спокойное, без агрессивных счётчиков потерь и обязательных длинных анимаций.
7. Обучение объясняет обещание, минимум, грэйс-день, награду и последствия на коротких примерах.

Google/Apple-вход и восстановление доступа относятся к ранее запрошенному развитию. Визуальные состояния можно подготовить в той же системе; их нельзя считать частью готовой авторизации лишь по наличию кнопки.

## 21. Настройки, данные и документы

### 21.1. Настройки

- Сохранить показ «Не сегодня».
- Сохранить фактическое поведение автоматического итога дня; не рисовать выключатель, который ничего не отключает.
- Сохранить напоминания, утреннее время, условное вечернее напоминание и вечернее время.
- Запрашивать системное разрешение на уведомления после осознанного включения; отказ имеет путь в системные настройки.
- Недоступные в браузере нативные настройки показывать в соответствии с реальными возможностями платформы.
- Добавленный в макете режим уменьшения движения согласовать с системной настройкой и сохранить его в профиле/настройках при переносе.

### 21.2. Данные

1. Экспорт JSON с прежним составом данных.
2. Импорт с проверкой файла и объяснением фактического способа объединения/замены.
3. Ошибка импорта не повреждает текущие данные.
4. Очистка требует явного подтверждения и объясняет, какое пространство очищается.
5. Импорт и смена устройства сохраняют цвета, сцены, предметы, биты и настройки.

### 21.3. Документы

Политика конфиденциальности оформляется отдельной читаемой страницей: заголовок, дата версии, подзаголовки, абзацы 16/24, ссылки и возврат. Визуальный редизайн не означает юридическую переработку текста; ранее запрошенная редакция политики остаётся отдельной работой.

## 22. Блокировка приложений и другие незавершённые возможности

В текущей версии реальная блокировка других приложений недоступна. Сохранить это состояние в форме, деталях старых обещаний и настройках. Старые записи остаются видимыми, без фиктивного включённого таймера и без автоматической замены на денежное последствие.

Ранее выбранный пользователем охват — Android и iOS. Для будущей рабочей реализации подготовить экраны выбора приложений, запроса разрешения, активного ограничения, завершения и отзыва доступа. Их реализация и проверка на устройствах идут отдельным нативным этапом.

То же правило применяется к неподключённым платежам, OAuth, возврату депозита и новым персонажам: проектировать состояние доступности честно, а не заполнять пробелы демонстрационными успешными действиями.

## 23. Иконки, иллюстрации и материалы

1. Иконки одного семейства с одинаковой оптической плотностью; базовый размер 24, обводка около 1,8–2.
2. Объём кнопок создаётся подложкой, аккуратной кромкой и короткой тенью. Нельзя ухудшать узнаваемость самой пиктограммы.
3. Детализированные иллюстрации используются в сценах, персонаже, снаряжении и медалях.
4. Мелкие служебные иконки остаются простыми; фактуры не переносятся в текст и таблицы.
5. На кнопке с одной иконкой есть доступное название; подсказка не заменяет его.
6. Светлое стекло не распространяется на финансовые данные, длинные формы и все карточки подряд.
7. Под каждой иллюстрацией предусмотрено место для текста; текст не впечатывается в растровый фон.

## 24. Анимационная система

| Событие | Движение / время | Что сохраняется без движения |
|---|---|---|
| Нажатие кнопки | Scale 0,97, 100–160 мс | Изменение цвета/состояния |
| Смена вкладки | Мгновенная смена, без поездки всего экрана | Активный раздел и позиция |
| Диалог | Opacity + scale 0,96→1, 200–250 мс | Короткое появление opacity |
| Шторка | Спокойный вход до 250 мс; закрытие симметрично | Короткая смена opacity |
| Изменение прогресса | Transform, 200–250 мс | Итоговое значение |
| Тост | Opacity + небольшое смещение, около 200 мс | Текстовое уведомление |
| Шаг марафона | Примерно 700 мс, согласованные части тела | Статичный результат и счётчик |
| Открытие предмета / финиш | Один короткий акцент, без бесконечного цикла | Открытый предмет / итог |

Основные кривые: `cubic-bezier(0.23, 1, 0.32, 1)` для появления; `cubic-bezier(0.77, 0, 0.175, 1)` для перемещения. При переносе использовать общие токены.

Анимация не задерживает запись данных и не блокирует выход. Быстрые повторные действия не запускают очередь эффектов. В списках нет постоянного покачивания, свечения и движущихся чисел. Системное уменьшение движения действует на все сцены, включая будущие.

## 25. Сквозные состояния и доступность

Каждый экран с данными получает: normal, loading, empty, error, offline и недоступность функции, если она возможна. Сохранение имеет pending/success/failure. Финансовые операции и приглашения дополнительно показывают ожидание внешнего подтверждения.

1. Скелетон повторяет геометрию контента; не подставляет случайные имена, балансы и достижения.
2. Ошибка содержит конкретное действие: повторить, исправить поле, открыть настройки.
3. В offline видны последнее сохранённое состояние и доступность действий. Неподтверждённый результат не выдаётся за окончательный.
4. Все действия доступны клавиатурой; диалог удерживает фокус и возвращает его на исходный элемент.
5. Системная кнопка назад сначала закрывает верхний слой.
6. Семантика: действие — button, навигация — ссылка; поля имеют label, статус — доступное объявление.
7. Клавиатура, вырез экрана и home indicator не перекрывают основной контрол.
8. Контраст проверяется на обычных, активных и стеклянных поверхностях.
9. Увеличенный текст и длинные русские подписи не требуют горизонтальной прокрутки страницы.
10. Состояния повторного клика и двух запросов одновременно не создают двойную запись.
