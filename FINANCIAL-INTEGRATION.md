# Disbit: закрытая денежная интеграция (РФ)

Состояние на 25 октября 2026: выбран первый кандидат **ЮKassa**. Platega не подключена. Владелец подтвердил, что отдельного магазина Disbit и письменного согласования схемы пока нет. Поэтому `PAYMENTS_PROVIDER=disabled` на production и staging остаётся обязательным; реальные пополнения, удержания и возвраты **не включены**.

## 1. Правила для согласования

Предлагаемая модель: пользователь вносит рубли, при невыполнении заранее принятого обещания штраф удерживается **только из доступного остатка**, а свободный остаток возвращается на исходный способ оплаты. Получатель удержания первого релиза — оператор Disbit («создателям»). Нет списания сверх депозита, отрицательного баланса, перевода на чужую карту и денежного обмена битов.

До включения нужны письменные ответы юриста и ЮKassa: правовая природа внесённого остатка и удержания, допустимость именно такого сценария по договору магазина, реквизиты оператора, фискальные чеки на каждом этапе, возраст/лимиты, возвраты и спорные случаи, пользовательская оферта, политика данных и тексты явного согласия. Текущие суммы 50–50 000 ₽ — границы прототипа, не утверждённый тариф. Подробный пакет вопросов: [RELEASE-RF-RULES.md](RELEASE-RF-RULES.md).

Документация провайдера, на которую опирается кандидат: [формат API и ключи идемпотентности](https://yookassa.ru/developers/using-api/interaction-format), [уведомления](https://yookassa.ru/developers/using-api/webhooks), [полный и частичный возврат на исходный способ](https://yookassa.ru/developers/payment-acceptance/after-the-payment/refunds). Эти страницы описывают технические возможности, а не одобрение бизнес-модели Disbit.

## 2. Что подготовлено в коде

- Таблицы `money_*` отделены от старых `wallets`/`transactions`. Исторический тестовый баланс не становится реальным и не подлежит возврату.
- Платёжное намерение создаётся с устойчивым ключом повтора. Ответ провайдера привязывается только при совпадении идентификатора намерения, валюты и суммы. Зачисление допускается только по объекту, заново запрошенному через аутентифицированный API магазина; тело webhook и возврат браузера не зачисляют деньги. Повтор подтверждения даёт одну проводку.
- Возврат резервирует доступный остаток, делится по исходным платежам, использует отдельные ключи повтора и уменьшает баланс только после подтверждения провайдера. Неизвестный результат оставляет резерв до сверки; отменённый возврат освобождает его.
- Штраф рассчитывается сервером только за закрытый день в часовом поясе аккаунта и по сохранённой версии явно принятых условий. Для недельной цели обязательность наступает, когда закончился запас дней. Архив, выполненная цель, согласованный пропуск и действительный пруф исключают штраф; ожидающий проверки пруф откладывает решение. Недостаток свободного остатка фиксируется без минуса и без последующего скрытого долга.
- Пропуск обещания и пропуск фото/видео учитываются раздельно. Сервер выдаёт до 5 бесплатных пропусков обещания на аккаунт за месяц и позволяет купить максимум 3 по 20 подтверждённых битов. Покупка повторяется с тем же идентификатором без второго списания битов. Квитанция пропуска сохраняется после редактирования отметки или удаления обещания. Для денежного освобождения нужен именно серверный чек пропуска; произвольное поле `skip` в истории его не заменяет.
- Покупку пропусков финансируют только биты, заработанные новыми серверно подтверждёнными выполнениями: пропуск пруфа учитывается сразу, загруженное фото/видео — после одобрения модератором. Ожидающий или отклонённый пруф не даёт расходуемый бит. Старый баланс `profile.bit` хранится на клиенте и пригоден только для косметики; он не даёт пропусков денежного обязательства. При отмене выполнения или отклонении ранее одобренного пруфа уже потраченный бит становится долгом в серверном балансе, чтобы повторное переключение отметки не создавало новые покупки.
- `money_terms` требует номер и SHA-256 опубликованного соглашения. Новые условия начинают действовать завтра, недельные — с ближайшего понедельника. Обещание с такими условиями нельзя физически удалить; изменение финансовых полей без нового принятия блокируется.
- Клиентский `/api/charges` помечен как историческая симуляция. Если позже включат live-режим, он вернёт 410: телефон не сможет отправить дату и инициировать реальный штраф.
- 31 автоматический тест проходит, в том числе совпадение сумм, повторы, поддельный webhook, возвраты, резерв, недельная норма, отклонённый пруф и лимит пропусков.

## 3. Почему функция пока закрыта

Новый денежный сервис **не подключён к публичным API и фоновому worker**. `backend/lib/runtime.js` по-прежнему запрещает `yookassa` в hosted-среде. В production нет ключей отдельного магазина Disbit и нет согласованного договора. Такой код можно проверять на искусственных данных, но им нельзя принимать средства пользователей.

Перед открытием переключателя необходимо:

1. Утвердить документы и получить отдельный магазин Disbit; определить чеки и лимиты.
2. Добавить аутентифицированные API для намерения, истории реального кошелька, заявки на возврат и принятия версии условий. Экран должен показывать сумму/получателя/срок/последствия до согласия.
3. Подключить секреты через root-only env, настроить HTTPS webhook и подписки на события платежей/возвратов. Никогда не копировать секрет старого магазина в репозиторий.
4. Запустить отдельный worker закрытия дней и сверки платежей/возвратов с журналом, блокировку при аномалии, мониторинг и операторский разбор зависших резервов.
5. Проверить чековый контур, поддерживаемые способы оплаты и возврата, частичный возврат, потерю webhook, таймаут и одновременный штраф/возврат в sandbox провайдера.
6. Выполнить независимый финансовый и security review, резервное восстановление и ограниченную live-приёмку с явным согласием владельца.

До этого интерфейс должен честно говорить «Пополнение и возврат пока недоступны». Текущие тестовые штрафы не являются движением реальных денег.
