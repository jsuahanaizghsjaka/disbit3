## Проблема

Барабан выбора срока, шагов, дней награды и времени перерисовывает содержимое всех колонок на каждом событии движения указателя. В `frontend/path-motion.js:209–221` функция `draw()` удаляет пять строк и создаёт пять новых:

  drum.setAttribute('aria-valuemin', min); drum.setAttribute('aria-valuemax', max()); drum.setAttribute('aria-valuenow', draft[index]);
  up.disabled = draft[index] <= min; down.disabled = draft[index] >= max();

## Целевой результат

1. Каждая колонка барабана имеет постоянные пять строк. Во время жеста в DOM не добавляются и не удаляются строки.
2. Обработка `pointermove` объединяется в максимум один `requestAnimationFrame` на кадр. Событие сохраняет координату; callback выполняет обновление.
3. Текст, `aria-valuenow`, ограничения и состояния кнопок меняются только при изменении целого значения или зависимого диапазона. Остаточное смещение меняется непосредственно в `strip.style.transform`.
4. Сохраняются размеры: строка `40px`, окно `200px`, пять строк, текущие границы значений и формат дат/времени.
5. Нажатия `+`/`−`, wheel и отпускание доводятся к выбранной строке за `180ms cubic-bezier(0.23, 1, 0.32, 1)`. Новое действие начинает движение от фактической видимой позиции. Новый drag немедленно перехватывает положение без скачка. Клавиатурное изменение и reduced motion не добавляют пространственного движения.
6. Переключатель использует постоянные габариты `32px × 24px`. Позиция `0px`/`22px` записывается непосредственно в transform наружного элемента `.as-thumb`. Внутренний `.as-thumb-art` отвечает за растяжение и визуальное оформление.
7. Сохранить нынешнюю видимую форму нажатия без анимации размеров: `scaleX(1.3125) scaleY(1.125)` соответствует прежним `42px × 27px` при исходных `32px × 24px`; origin — центр. Выход из нажатия — `scale(1)`.
8. Переключение и растяжение используют `140ms cubic-bezier(0.23, 1, 0.32, 1)`. Во время drag transition позиции выключен. Цвет меняется за `140ms ease`. Семантика переключения и сохранения настроек остаётся прежней.

Целевой CSS переключателя:

```css
.as-thumb {
  position: absolute;
  top: 50%; left: 4px;
  width: 32px; height: 24px;
  transform: translate(0, -50%);
  transition: transform var(--motion-press) var(--ease-out);
}
.as-thumb-art {
  display: block;
  width: 100%; height: 100%;
  border-radius: inherit;
  transform-origin: center;
  transition: transform var(--motion-press) var(--ease-out);
}
.aswitch.grabbing .as-thumb-art { transform: scale(1.3125, 1.125); }
.aswitch.dragging .as-thumb { transition: none; }
```

Фон, тени и радиус нынешнего `.as-thumb` перенести во внутренний `.as-thumb-art`; элемент позиции не должен добавлять второй визуальный слой.

## Соглашения проекта

- Действующие токены заданы в `frontend/path-support.css:2`: `--motion-press:140ms`, `--motion-ui:180ms`, `--ease-out:cubic-bezier(.23,1,.32,1)`. Использовать их, не создавать второй набор похожих токенов.
- `motionReduced()` в `frontend/path-motion.js:8–10` учитывает настройку Disbit и системный режим. Использовать эту функцию при запуске WAAPI и в обработчике жестов.
- `openDisbitWheel()` уже держит `draft` отдельно от backing input и сохраняет только по «Выбрать» (`frontend/path-motion.js:265–270`). Сохранить эту модель.
- `initSwitch()` уже предотвращает двойной click после перетаскивания и поддерживает клик по подписи (`frontend/script.js:4438–4466`). Сохранить эти гарантии.
- `role="spinbutton"`, `aria-valuemin/max/now`, `role="switch"` и `aria-checked` остаются источниками состояния для доступности.

## Подшаги реализации

1. **Зафиксировать исходное поведение.** На текущем commit записать значения wheel до/после `+`, `−`, wheel, drag, Home/End и отмены. На тестовых настройках проверить один вызов `onChange` за изменение переключателя. Не использовать денежные действия для бенчмарка.
2. **Сделать постоянный пул строк в `openDisbitWheel()`.** Создавать пять `span` один раз при создании колонки. Хранить ссылки в массиве. Разделить нынешний `draw()` на обновление значений/ARIA и обновление transform. Внутри обработки движения не использовать `replaceChildren`, `createElement`, `append`.
3. **Обновлять только зависимости.** У каждой колонки хранить последнее отображённое целое значение и диапазон. Изменение месяца/года пересчитывает максимум дней и при необходимости ограничивает день; изменение дня не перерисовывает год и месяц. Изменение часов не перерисовывает минуты.
4. **Объединить события drag в один кадр.** `pointermove` сохраняет последнюю координату и запрашивает rAF, если его ещё нет. rAF вычисляет целое значение и остаток, затем обновляет только нужные свойства. `pointerup` сначала применяет последнюю сохранённую координату, затем запускает доводку.
5. **Сделать прерывание непрерывным.** Для дискретного изменения считывать фактический текущий transform один раз перед отменой существующей WAAPI. Записывать его как старт новой анимации. Не начинать каждое повторное нажатие с фиксированного `±40px`. Не считывать layout внутри каждого `pointermove`. При новом drag отменять анимацию после сохранения её видимого положения.
6. **Довести release.** Плавно довести остаточное смещение к нулю за `180ms` с `--ease-out`. Не добавлять инерцию, меняющую выбранное число после отпускания: это отдельная продуктовая опция вне этого исправления. На границах сохранить ограниченные значения и отсутствие переполнения.
7. **Убрать незавершённые callback.** На `pointercancel`, `lostpointercapture`, `dialog.close`, скрытие страницы и смену reduced motion отменять pending rAF/WAAPI, освобождать захват и очищать состояние. Отмена диалога не пишет draft в input. Нажатие «Выбрать» применяет последнее значение ровно один раз.
8. **Разделить позицию и рисунок переключателя.** В четырёх текущих переключателях `frontend/index.html:508–512`, `517...`, `537–541`, блоке вечернего напоминания добавить внутрь `.as-thumb` единственный `<span class="as-thumb-art" aria-hidden="true"></span>`. Не добавлять интерактивных вложенных элементов.
9. **Перенести оформление и убрать layout transitions.** Применить целевой CSS. Удалить зависимость width/height от `--as-extra`, transitions width/height и позицию через `--as-x`. После переноса `.as-thumb-art` имеет прежние фон/тени/радиус. Убедиться, что более поздний CSS не возвращает прежние размеры.
10. **Объединить все записи позиции.** Создать одну функцию установки позиции на дочернем `.as-thumb`, хранящую текущее числовое положение. Использовать её в `initSwitch` и текущих местах `script.js:2429`, `5069`, `5073`. `curX` читает сохранённое число, а не вычисленные CSS или DOM-геометрию на каждом движении.
11. **Обработать reduced motion и клавиатуру.** В reduced motion мгновенно установить целевой transform и отключить растяжение. При Space/Enter переключать состояние без пространственной анимации согласно существующей `data-input="keyboard"` политике. В обычном touch-режиме оставить обратную связь нажатия.
12. **Записать результат сравнения.** В проверочный отчёт включить объём добавленных/удалённых DOM-узлов во время одного drag, число rAF callback, trace главного потока и запись одного быстрого перебора. Отдельно отметить условия устройства и версию WebView.

## Границы

- Не менять лимиты дней, шагов, даты, формат времени, расчёт марафона и хранение настроек.
- Не сокращать удержание подтверждающих кнопок: `1000ms` относится к отдельному механизму намеренного подтверждения.
- Не менять денежные условия, операции, серверные запросы и подтверждения списаний.
- Не менять палитру, Glass Light, размеры touch-target и макет остальных экранов.
- Не добавлять анимационную библиотеку, React или новый gesture framework. Для этой задачи достаточно DOM, CSS transform, WAAPI и rAF.
- Не анимировать `width`, `height`, `left`, `top`, padding или margin. Не вешать transform-переменные на родителя ради движения детей.
- Не добавлять постоянный цикл rAF: он существует только пока идёт жест/доводка и завершается при покое.
- При расхождении указанных фрагментов с рабочим commit сначала обновить план/согласовать новые точки правки; не применять замену вслепую.

**Браузерные сценарии:**

- 20 быстрых `+`/`−`, быстрый wheel туда/обратно, drag с изменением направления, отпускание в середине строки, cancel/закрытие диалога во время движения.
- Через `MutationObserver` убедиться: после первичного открытия колонки во время drag число `childList` вставок/удалений внутри `.motion-wheel-strip` равно нулю.

**Проверка ощущения:**

- DevTools Animations на скорости 10%: wheel не прыгает к фиксированному стартовому смещению при втором нажатии; палец перехватывает текущую позицию.
