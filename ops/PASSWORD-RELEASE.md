# Выпуск восстановления пароля — 3 ноября 2026

## Контракт

- Вход → «Забыли пароль?»; профиль → «Настройки» → «Изменить пароль».
- Код из письма — 64 шестнадцатеричных символа, действует 15 минут. Ввод связан с подтверждённой почтой. Код одноразовый; новый запрос заменяет старый.
- Успех завершает все серверные сессии аккаунта. Клиент удаляет свой токен, сохраняет локальные данные и черновики и предлагает повторный вход.
- Из профиля сначала выполняется синхронизация состояния. При её ошибке смена не выполняется, выводится объяснение.
- Запрос кода: одинаковый ответ для неизвестной, неподтверждённой почты, превышения квоты и ошибки отправки. Одинаковая минимальная задержка ответа, SMTP не задерживает ответ.
- Лимиты хранятся в SQLite: 3 запроса на адрес в час, 20 на IP за 15 минут, 100 глобально за 15 минут. Подтверждение: 30 на IP и 300 глобально за 15 минут. SMTP cooldown 60 секунд. Глобальные лимиты — защитный предел; при росте аудитории нужны метрики и пересмотр значений.
- Сервер доверяет forwarded IP только соединениям с loopback (Caddy). Приложение должно оставаться привязано к 127.0.0.1.
- Отправка не является устойчивой очередью: остановка процесса во время SMTP может прервать письмо. Пользователь повторяет запрос; код и пароль не журналируются. При штатной ошибке недоставленный код удаляется.

## Локальные проверки

`npm test` — 50 тестов, включая лимиты после перезапуска, чужой код/почту/сессию, срок, одноразовость, старый пароль, отзыв сессий, сбой SMTP, повторную отправку и журналирование.

Playwright CLI / Chrome: восстановление с экрана входа, несовпадающие пароли, Enter, новый вход; профиль на ширине 360 px, подстановка почты, сбой синхронизации без смены пароля, сохранность черновика после перезагрузки, повторный вход. Использована изолированная БД и синтетическая почта. Это не доказательство доставки реального письма.

Фикстура: `tests/recovery-fixture.mjs`; переменная RECOVERY_TEST_OUTBOX может указывать на файл в игнорируемом release-artifacts. Только тестовые письма. `tests/browser-password-recovery.js` запускается через playwright-cli с подстановкой синтетического кода вместо __CODE__.

## Условия публикации

1. Зафиксировать кандидат, проверить чистоту включённых файлов; не включать локальные данные, архивы, секреты.
2. Staging: отдельная БД, платежи выключены, SMTP Timeweb. Пройти регистрацию и оба пути восстановления с настоящим письмом.
3. Создать offline-снимок production-БД и медиа. Проверить manifest, SQLite, восстановить в новый закрытый каталог.
4. Сохранить ссылку current и конфигурацию предыдущей версии. Разместить архив конкретного SHA в новом каталоге.
5. Переключить current и RELEASE_SHA, включить PASSWORD_RESET_ENABLED только после успешного staging. Проверить ready/health локально и по HTTPS и реальный тестовый вход.
6. Собрать APK 1.0.7 (8), сохранить SHA-256. Debug APK не является подписанным магазинным релизом. Проверку установки отдельно фиксировать по фактическому устройству.

## Откат

При ошибке запуска вернуть прежнюю ссылку current и прежние release-настройки, перезапустить disbit, проверить /api/ready и /api/health. Этот выпуск не меняет схему данных. Откат кода не откатывает сменённые пользователями пароли: это нормальное сохранение новых данных.

Нельзя автоматически заменять рабочую БД резервной копией: потеряются действия после снимка. Восстановление БД — только при установленной порче данных, остановленных писателях и отдельном решении оператора.

## Мониторинг и действия

`scripts/monitor.mjs`, `ops/disbit-monitor.service`, `ops/disbit-monitor.timer`: каждые 5 минут проверять local ready, внешний HTTPS, disbit/Caddy, свободное место, изменения старта служб и NRestarts, ошибки почты в journal. Порог места: 90% занято или менее 1 ГиБ свободно. Уведомление при изменении состояния, восстановлении и раз в час при сохраняющейся проблеме. Данные мониторинга в /var/lib/disbit-monitor, адрес в /etc/disbit/monitor.env (0600). SMTP credentials берутся из существующего закрытого env, не из репозитория.

Пробный сигнал: запуск с `--self-test`. SMTP accepted подтверждает передачу провайдеру; получение письма подтверждает получатель.

- unavailable/service: systemctl status disbit caddy, curl localhost /api/ready, journalctl; сверить SHA и RELEASE_SHA. При связи с выпуском выполнить откат кода.
- disk: df -h, du по /srv и /var/log. Не удалять БД, медиа и единственный проверенный бэкап. Для чистки выбирать подтверждённые устаревшие артефакты; расширение диска согласовывать по текущему тарифу.
- restart: сверить время с плановым выпуском; иначе смотреть OOM/ошибки запуска и журнал ядра.
- mail: проверить Timeweb SMTP и состояние ящика, доступность 465, конфигурацию без вывода секретов. Проверить отдельное тестовое письмо, затем повторную отправку в приложении.
- monitor failed: проверить unit и journal; не считать отсутствие письма доказательством исправности.

Ограничение: монитор на том же сервере не уведомит при полной потере сервера/сети; при отказе SMTP канал уведомлений также недоступен. Для покрытия этих отказов нужен внешний независимый монитор и второй канал уведомлений.

## Приёмка

Фактический SHA, staging/production результаты, backup/restore, сборка APK, доставка уведомления и непроверенные платформы фиксируются отдельно в отчёте. До этого статус выпуска — кандидат. Настоящие Android/iOS и реальная SMTP-доставка не заменяются эмуляцией размеров браузера.
