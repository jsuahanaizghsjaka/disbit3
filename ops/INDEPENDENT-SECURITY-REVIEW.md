# Disbit — пакет знакомому разработчику

Подготовлено 16 ноября 2026. Это задание на независимую проверку, не заключение аудита. Получатель ещё не назначен. Production, реальные платежи, реальные пользовательские данные и секреты не входят в разрешённый стенд.

## Подготовка владельцем

Перед передачей зафиксировать SHA проверяемой версии, отдельный staging URL и срок доступа. Выдать два новых тестовых аккаунта A/B с подтверждёнными адресами проверяющего, отдельный ограниченный доступ к тестовой панели модерации. Не передавать production ADMIN_KEY, SMTP/OAuth/SSH-ключи и базу. Пароли передать отдельно от отчёта. Ограничить стенд по IP, настроить изолированную БД/медиа, тестовую почту и отключённые платежи. После проверки отозвать доступы.

Для самостоятельного локального воспроизведения: Node 24, `npm ci`, `npm ci --prefix backend`, `npm test`. Синтетический сервер: `node tests/recovery-fixture.mjs`; привязан к тестовым временным данным, почтовый транспорт подменён. Не выставлять fixture наружу. Нагрузку запускать только отдельным `node tests/phase4-load.cjs`, не перенаправлять на рабочий домен.

## Чеклист независимого аудита

- [ ] Сессии: без токена, токен B при id A, поддельный/истёкший токен, выход, смена пароля и отзыв старых сессий.
- [ ] Регистрация/восстановление: отсутствие перечисления адресов, чужой/неверный/истёкший/повторный код, лимит после перезапуска, ошибки почтового транспорта без утечки секрета.
- [ ] OAuth: state/nonce/redirect, replay, неправильные issuer/audience/signature, явное связывание с существующим аккаунтом. Не использовать рабочие Google/Apple секреты.
- [ ] Приватность A/B: /state, /habits, friends/invites, экспорт, удаление, кошелёк. B не читает/изменяет/удаляет данные A; недоступное должно давать 401/403/404, не успешный пустой ответ с побочным изменением.
- [ ] Пруфы: чужой habitId, день не сегодня, архив, размер >5/10 МБ, MIME/сигнатура, видео >15 секунд, отсутствие ffprobe, оборванная отправка, параллельные загрузки. Проверить файлы на диске после отказа.
- [ ] /proofs и /proofs/:id/media закрыты обычным пользователям. Админ-ключ не появляется в HTML, localStorage, URL, журналах и экспорте.
- [ ] Источник gallery/camera/unknown в модерации; проверить, что подпись не представляется криптографическим доказательством. HTML в имени/логине не выполняется.
- [ ] Модерация: жалоба, блокировка, обжалование, снятие ограничения, повтор решения, попытка обойти ограничения через прямой API.
- [ ] Два клиента: stale baseUpdatedAt получает 409; локальные данные не теряются до подтверждения пользователя. Повтор отметки/покупки не даёт двойной награды/списания.
- [ ] Биты: 20 за дополнительный пропуск, не более 3 покупок в месяц, нехватка баланса, конкурентные запросы, общий дневной пропуск для всех обещаний.
- [ ] Проверить логи на пароли/коды/токены/медиа и права файлов; удаление аккаунта/медиа, журнал исключения из восстановления.

## Что приложить к каждому дефекту

SHA, окружение, время UTC, предусловия A/B, шаги и минимальный запрос с удалёнными токенами, ожидание/факт, код ответа, влияние, повторяемость, безопасное доказательство. Уровни: критический — чужие данные/деньги/полный обход авторизации; высокий — устойчивый обход ограничений/сессий; средний — ограниченная утечка/потеря данных; низкий — сообщение/UX без обхода защиты. Не включать в отчёт реальные данные.

## Условие закрытия

Проверяющий самостоятельно подписывает результат по каждому пункту: PASS/FAIL/NOT TESTED, указывает SHA. Все критические/высокие дефекты устранены и повторно проверены им. Отдельно перечислены ограничения. До этого пункт «независимый аудит» остаётся открытым.
