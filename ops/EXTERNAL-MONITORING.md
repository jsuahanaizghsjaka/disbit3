## Действия при уведомлении

1. Открыть инцидент в Better Stack, посмотреть время, URL, сетевую ошибку или ответ сервера. Сопоставить обе проверки: отказ API при доступном сайте отличается от полной недоступности домена.
2. Проверить сайт с другого подключения. Сбой только рабочего компьютера не считать доказательством полного отказа сервера.
3. В Timeweb проверить питание сервера и баланс. При доступном SSH проверить службы Disbit/Caddy, свободное место и журналы по инструкции `ops/PASSWORD-RELEASE.md`.
4. Если проблема началась после публикации, выполнить подготовленный откат кода. Не заменять рабочую базу старой копией автоматически.
5. После исправления дождаться автоматического восстановления монитора. Если выполнена только ручная отметка инцидента, она сама по себе не подтверждает доступность.

## Оставшиеся ограничения

- Тестовое уведомление попало в спам. Нужно отметить его как «Не спам» в Gmail, затем повторить Send test alert и проверить попадание нового письма во входящие. Эти действия ещё не подтверждены; до проверки остаётся риск пропустить уведомление.
- Реальная авария и полный цикл Down → уведомление → Up не имитировались; рабочий сайт для проверки не останавливался.
- Предупреждения о приближении срока сертификата/домена требуют платного тарифа в данном кабинете и не включены. Проверка действительности TLS включена.
- Этот монитор не проверяет доставку писем, вход пользователей, платежи, диск и состояние внутренних служб. Серверный мониторинг дополняет его, но его состояние в этой настройке повторно не проверялось.
- Первоначальный демонстрационный инцидент `google.com Sample incident` существовал до настройки и не относится к Disbit; он не изменялся.
